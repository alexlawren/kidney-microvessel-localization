# Постоянные инструкции

- Python 3.12, src/kidney_vessels, строгая типизация. Комментарии/docstring на русском,
  имена в коде на английском.
- Перед изменениями прочитать README.md, docs/architecture.md и docs/dataset-audit.md.
- domain зависит только от стандартной библиотеки; Pillow/Shapely/ML остаются в адаптерах.
- Предпочитать композицию и функции; Protocol/ABC вводить при реальной заменяемости.
  Не создавать пустые ML-модули, интерфейсы и будущие функции без задачи.
- Исходные изображения, метки, координаты и метаданные не изменять. Производные
  представления хранить отдельно с параметрами и происхождением.
- Не считать пустоту/отсутствие разметки отрицательным примером; unsure не становится
  целевым классом. Dataset 1/2/3 имеют разные статусы; качество и полнота независимы.
- Постановка детекция/сегментация и один/три класса не согласованы. Подтипы сосудов
  нельзя выводить из blood_vessel без экспертной разметки.
- Фактический формат новых данных проверять до написания адаптера и сохранять источники.
  HuBMAP из проекта практики подключается по локальному пути. Различать реальные и
  синтетические прогоны. Результаты первого реального прогона описаны в docs/practice-audit.md.
- Зависимости: uv sync --locked; обновлять uv.lock осознанно вместе с pyproject.toml.
- Новое поведение и исправления проверять тестами. Тесты автономны, без GPU/сети/HuBMAP.
- Не добавлять data/, reports/, веса моделей, окружения, секреты и генерируемые артефакты в Git.
  Не перезаписывать непустые отчёты; при повторном аудите использовать новый output.

## Работа с Git

- Следовать [GitHub Flow проекта](docs/git-workflow.md). Перед новым change-set проверить
  статус, ветки и remote. Создать отдельную ветку от актуальной `main` с префиксом
  `feat/`, `fix/`, `refactor/`, `docs/`, `test/` или `chore/`.
- `main` — стабильная ветка. Вести разработку в рабочих ветках. Постоянные `develop`
  и `release` вводить только при обоснованной необходимости.
- Делать осмысленные Conventional Commits. Перед коммитом проверять staged diff,
  включая имена файлов, и добавлять в индекс только файлы текущей задачи.
- Перед завершением выполнить `uv run --locked pytest`, `uv run --locked ruff check .`,
  `uv run --locked ruff format --check .`, `uv run --locked mypy`, `uv build` и проверки,
  специфичные для изменения. В сводке указать изменения, результаты, ветку и коммиты.
- Готовить изменения к Pull Request в `main`. Публикация ветки, создание PR от имени
  пользователя, merge в `main`, force push, удаление веток и изменение remote или
  настроек GitHub требуют явного согласия владельца.
