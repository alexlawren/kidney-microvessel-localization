# Контракт и ограничения аудита HuBMAP

## Проверенные источники

09.11.2026 выполнен реальный аудит локальной копии HuBMAP из проекта практики.
Прочитаны все 7 033 TIFF из `train/`, исходный JSONL и обе таблицы CSV.
Результаты и команды повторения собраны в [отчёте о практике](practice-audit.md).

При первоначальной проверке формата 02.11.2026 использовались следующие источники.

- [Официальная страница HuBMAP — Hacking the Human Vasculature](https://www.kaggle.com/competitions/hubmap-hacking-the-human-vasculature/data).
  Страница доступна как веб-приложение, но её описание не удалось получить текстовым
  просмотром; это ограничение не выдаётся за проверку содержимого архива.
- Проверены реальные первые строки
  [tile_meta_7033.csv](https://github.com/innolitics/kaggle-HuBMAP/blob/main/metadata/tile_meta_7033.csv)
  и полный маленький [wsi_meta.csv](https://github.com/innolitics/kaggle-HuBMAP/blob/main/metadata/wsi_meta.csv).
  Это публичная копия участника, а не первичный архив организаторов.
- Проверен фрагмент реально сохранённой разметки в
  [polygons_1633.csv](https://github.com/innolitics/kaggle-HuBMAP/blob/main/metadata/polygons_1633.csv):
  `id,annotations`, объект `type: glomerulus`, `coordinates: [[[167,249], ...]]`.
  Это производное CSV-представление; оно **не** читается вместо исходного JSONL.
- [Код подготовки данных автора решения](https://github.com/tascj/kaggle-hubmap-hacking-the-human-vasculature/blob/master/tools/prepare_data.py)
  непосредственно читает `json.loads(line)`, `ann['id']`, `ann['annotations']`,
  `ann['type']`, `ann['coordinates']`; координаты — список компонентов, каждый
  компонент — список пар. Код послужил первичным свидетельством поведения адаптера.
- [Описание изученных данных участником](https://github.com/innolitics/kaggle-HuBMAP)
  фиксирует группы 1/2/3 и отсутствие разметки в третьей. Эти сведения нужно
  перепроверить по поставляемой версии официального архива при его подключении.

Контракт подтверждён на локальных исходных файлах практики. Воспроизводимость
прогона обеспечивают хеши фактически прочитанных файлов в `manifest.json`.

## Входные поля

```json
{"id":"tile_id","annotations":[{"type":"blood_vessel","coordinates":[[[1,1],[5,1],[5,5],[1,5]]]}]}
```

Это минимальный **синтетический** пример структуры, а не запись из настоящего JSONL.
Одна строка содержит запись тайла. Пустые строки пропускаются. `annotations: []`
означает пустую запись; отсутствие строки тайла — другое состояние.
`annotations: null`, отсутствующий список, неверный JSON, NaN/Infinity и числа
с переполнением float (`1e400`) — ошибки. Исходный текст ошибочной строки сохраняется.
Дополнительные поля объектов/записей сохраняются в исходном JSON и тексте строки.

`tile_meta.csv`: обязательные столбцы `id,source_wsi,dataset,i,j`.
Проверенные примеры: `0006ff2aa7cd,2,2,16896,16420`,
`000e79e206b7,6,3,10240,29184`.
`i,j` — исходные смещения в WSI, сохраняются без перестановки осей. Их соответствие
строке/столбцу WSI в этом этапе не предполагается; преобразование в WSI не выполняется.
Допускаются неотрицательные десятичные целые с ведущими нулями, например `08192`.
Исходная запись поля сохраняется в реестре. Проверка границ WSI требует его размеров.

`wsi_meta.csv`: ключ `source_wsi`; наблюдаемые дополнительные поля
`age,sex,race,height,weight,bmi`. Сохраняются все столбцы, в том числе неизвестные.
В проверенной копии есть только WSI 1–4, поэтому отсутствие строки для WSI 6+
возможно и само по себе не делает TIFF повреждённым. Пропуски наблюдаемых полей
в существующей строке дают `missing_wsi_field`. Ключ WSI не подменяет patient_id.
Явный `patient_id`, если он есть в дополнительном столбце tile/WSI, сохраняется;
при отсутствии — None. Шкалы микрометр/пиксель в проверенных столбцах нет.
Неизвестные дополнительные поля масштаба сохраняются как исходные метаданные,
но не интерпретируются без проверенного контракта единиц.

CSV допускает UTF-8 BOM и Windows CRLF. Исходные значения сохраняются строками.
Ключи индекса CSV очищаются от внешних пробелов; оригинальная строка остаётся в реестре.
Повторные ключи диагностируются, все строки сохраняются, индекс использует первую.
Неверное число столбцов, повтор заголовков или отсутствие обязательных заголовков
прерывают запуск, поскольку безопасное связывание такой таблицы невозможно.

## Семантика разметки

| Dataset | annotation_status | annotation_completeness |
|---|---|---|
| 1 | expert_reviewed | unknown |
| 2 | not_reviewed | sparse |
| 3 | unannotated | unannotated |
| Неизвестен | unknown | unknown |

Независимое `annotation_presence`: `present`, `empty`, `missing`, `invalid`.
Повторные JSONL-записи одного id и записи с ошибками объектов дают invalid.
Исходные объекты при этом сохраняются. Объекты Dataset 3 дают предупреждение
о противоречии заявленному статусу, а не молча меняют его.

Категории `blood_vessel`, `glomerulus`, `unsure` сохраняются буквально.
Они не являются заранее выбранными классами будущей модели. unsure учитывается
в аудите и контурном просмотре как неопределённая категория. Неизвестная непустая
категория сохраняется с предупреждением; отсутствующая/пустая — ошибка объекта.
Никакая пустота разметки не преобразуется в подтверждённый отрицательный пример.

## Проверки изображений и геометрии

- ID тайла — имя файла без расширения. Дубликаты ID среди разных файлов — ошибка;
  такие объекты не получают проверку границ и не входят в геометрическую статистику.
- Pillow полностью декодирует единственную страницу, а не только открывает заголовок.
  Повреждение, предупреждение декодера о целостности или несколько страниц дают ошибку.
  Режим и фактические размеры сохраняются;
  размер 512×512 не захардкожен, синтетические и другие размеры поддерживаются.
- Координаты — конечные числа (bool запрещён), ровно `[x,y]`, локальные пиксели,
  начало слева сверху. Допустимо `0 <= x < width`, `0 <= y < height`.
  Верхняя граница выбрана как индекс пикселя; объекты на `x=width` или `y=height`
  сохраняются как невалидные без обрезки. В проверенной локальной копии не обнаружено
  выходов координат полигонов за границы тайлов.
- Компонент содержит минимум три различные точки, положительную площадь;
  Shapely проверяет самопересечения, вырожденность и корректность MultiPolygon.
  Переполнение вычисленных площадей и bbox также отклоняется.
  Компоненты трактуются как независимые части объекта, не отверстия. Вложенные
  или перекрывающиеся компоненты отклоняются; иной контракт потребует явного адаптера.
- Повтор конечной точки допускается; в производном контуре она учитывается один раз.
  Другие повторные вершины диагностируются. `buffer(0)`, make_valid, округление,
  изменение порядка вершин и исправление исходных полигонов не применяются.
- Без читаемого однозначного изображения проверяется только топология; ставится
  `image_bounds_unchecked`, `bounds_checked=false`, `measurable=false`.

## Реестры и статистика

`images.csv`: одна строка на найденный поддерживаемый файл, включая повреждённые;
`image_id,path,readable,width,height,mode,source_wsi,patient_id,dataset`, статус,
полнота, наличие разметки, число объектов, координаты, scale, исходные метаданные и preview.
При дубликате файлов число объектов у каждого указывает на те же исходные записи:
**не** суммируйте его для определения общего числа объектов — используйте annotations.

`annotations.csv`: одна строка на исходный объект, включая невалидный и неизвестный.
ID `lineN:objectM` связывает его со строкой JSONL (N с 1, M с 0).
Содержит category, raw_json, ошибки, предупреждения, geometry_valid, bounds_checked,
measurable, component_count и производные метрики.

Площадь — сумма непрерывных площадей непересекающихся компонентов по формуле Гаусса.
Bbox: `x_min,y_min,x_max,y_max`; ширина/высота — разность границ, без `+1`.
Площадь bbox — их произведение. Эти значения не равны площади растровой маски.
В физические единицы ничего не переводится без проверенного масштаба.
`geometry_statistics` содержит count/min/max/mean/median для площади и трёх bbox-метрик
по исходным категориям; участвуют только measurable-объекты. Объекты повторных
JSONL-записей одного id исключены из статистики как неоднозначные, но сохранены в реестре.
unsure и неизвестные
категории сохраняют собственные строки. Пустой набор даёт CSV с заголовком и JSON `[]`.

Summary различает число файлов, уникальных id, читаемых файлов, JSONL-записей,
всех объектов, валидных геометрий и измеряемых объектов. WSI считаются по непустым
source_wsi найденных файлов, а не по количеству строк wsi_meta или пациентов.
Распределения категорий включают все объекты с непустой меткой, в том числе невалидные.

`registry.json` содержит полный текст каждой непустой JSONL-строки (в том числе
неразобранной), raw_json каждого объекта и все CSV-строки. Исходные файлы неизменны;
это не обещание побайтового архивирования BOM/CRLF/пустых строк в registry.
Оригинальная побайтовая идентичность контролируется SHA-256 в manifest.

## Диагностика и просмотр

Issues содержат `severity,code,message,source,image_id,annotation_id,line`.
Error: JSON/схема, геометрия, повреждение изображения, дубликаты и потерянные связи.
Warning: неизвестная категория/группа, пропуск метаданных, неподтверждённое покрытие.
Info: отсутствие явного пациента/масштаба, строки metadata без train-тайла (могут
относиться к test). Номера строк CSV/JSONL начинаются с 1.

PNG используют исходное разрешение, производную RGB-копию и контур толщиной 2 px.
Легенда RGB сохраняется в manifest и Markdown. Невалидные контуры не рисуются.
Первые примеры выбираются детерминированно: сначала тайлы с JSONL-записью, затем
остальные, внутри группы по id. Пустой пример показывает изображение без контуров;
это не доказательство отсутствия сосудов. Имена PNG генерируются безопасно и
связываются с id через images/manifest. Гистологическую корректность проверяет эксперт.
