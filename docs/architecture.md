# Архитектура обработки данных

## Границы ответственности

```text
CLI (argparse)
  ├─ application.audit → application.reports
  └─ application.prepare → preparation, splits
Оба сценария используют data.hubmap, data.images и preprocessing.
data.hubmap и preparation используют annotations (Shapely).
evaluation считает сегментационные метрики на бинарных масках.
Все перечисленные модули могут использовать domain; domain не использует их.
```

`domain.py` содержит frozen dataclass и перечисления: HistologyImage, ImageOrigin,
Point, SpatialScale, PolygonGeometry, SourceCategory, GeometricAnnotation,
AnnotationStatus, AnnotationCompleteness, AnnotationPresence и AuditIssue.
В домене нет NumPy, Pillow, Shapely или ML-библиотек. Изображение представлено
идентификатором, путём, размерами и происхождением; массивы не удерживаются в памяти.
`SpatialScale` хранит два положительных конечных размера пикселя в микрометрах.
В текущем HuBMAP-контракте такого масштаба нет, поэтому используется None.

`data/hubmap.py` знает структуру CSV/JSONL. Он сохраняет исходные строки и поля,
а производную геометрию получает через `annotations.validate_geometry`.
`data/images.py` изолирует полное декодирование одностраничных файлов и ошибки Pillow.
`preprocessing.py` создаёт RGB-копии и растровые маски объектов через Pillow.
В этом этапе подготовка использует готовые тайлы с исходными смещениями `i/j`.

`application/audit.py` задаёт последовательность чтения, связывания и подсчёта.
`AuditConfig` — явные параметры сценария; `AuditResult` — результат.
Реестры представлены словарями с объектными значениями на границе сериализации:
они не являются универсальной моделью будущего предсказания. Строгий mypy проверяет
код, но JSON-схема фиксируется тестами и `manifest.schema_version`.
`application/reports.py` отвечает за CSV, JSON, Markdown и контуры.
`cli.py` отвечает только за параметры, логирование и код завершения.

`application/prepare.py` экспортирует тайлы и положительные цели с манифестом.
`preparation.py` применяет политики пропуска, остановки и явной коррекции.
`splits.py` распределяет целые WSI по частям. Модуль `evaluation.py` зависит от
стандартной библиотеки и принимает готовые бинарные маски с явной областью оценки.
Для детекции можно добавить отдельные метрики сопоставления объектов по bbox,
используя ту же подготовку. Подробные соглашения приведены в
[руководстве по подготовке](data-preparation.md).

## Почему такая структура

Композиция простых сущностей и функций позволяет отдельно проверять геометрию,
парсеры и сценарий. Наследование/Protocol/ABC не вводятся, поскольку в текущем этапе
нет нескольких заменяемых реализаций. Отдельный универсальный репозиторий, DI-контейнер,
абстрактный тренер или общий интерфейс детектора и сегментатора были бы преждевременными.

Хранение исходного JSON рядом с производной геометрией позволяет позднее создать
экспорт масок, bbox или иных целей, не переписывая оригиналы. Категория — строковое
значение, а не индекс фиксированной нейросетевой головы. Dataset-специфические знания
об исходных трёх метках и группах 1/2/3 остаются в адаптере/сценарии.

Полигон — единственная геометрия текущего входного формата. Это не ограничение
будущих предсказаний: типы результатов модели и правила преобразования появятся
в следующем этапе, когда будет известна постановка. Не создаётся универсальное
поле с нетипизированным результатом нейросети заранее.

## Поток данных и ошибки

1. Проверяются обязательные пути и непересечение input/output.
2. CSV читаются с проверкой заголовков и количества полей; поля сохраняются строками.
3. Входные файлы хешируются; изображения полностью декодируются последовательно.
4. JSONL читается построчно; проверяются схема, категория, геометрия и связи.
5. Формируются независимые сведения о качестве, полноте и наличии разметки.
6. Все объекты записываются в реестр, валидная связанная геометрия — в статистику.
7. Сохраняются отчёты и детерминированно выбранные PNG-примеры.

Неверный каталог, заголовок/синтаксис CSV, ошибка чтения/записи — ошибка запуска
с понятным сообщением. Ошибки отдельных JSON-строк, объектов, TIFF и метаданных
попадают в issues, остальные данные обрабатываются. KeyboardInterrupt не подавляется.
Полный traceback для ожидаемых ошибок CLI не выводится. Логирование настраивает
только точка входа; прикладной код использует модульный logger.

## Воспроизводимость и ограничения

`uv.lock` фиксирует зависимости. Manifest сохраняет Python, ОС, версии библиотек,
Git revision и признак незакоммиченных изменений при запуске из исходников,
SHA-256 модулей самого приложения, параметры, SHA-256, размеры и относительные пути
входных файлов, правила геометрии и отображения. Время записывается в UTC.
Настройки будущих экспериментов и обработок должны сохраняться аналогично;
сейчас экспериментов обучения нет.

Порядок обхода и выбора примеров детерминирован, случайность генератора имеет seed.
При установке wheel Git revision может быть None, но хеши модулей сохраняются.
Время, абсолютные пути и Git revision между запусками могут различаться; сводные
счётчики и статистика одного и того же набора должны совпадать.
Input во время аудита должен быть неизменяемым: блокировка файлов/снапшоты не реализованы.
Реестры и исходный текст JSONL удерживаются в памяти, пиксели — по одному тайлу.
Это подходит для конкурсного набора тайлов, но не для потоковой обработки больших WSI.
Shapely отвечает за топологию, обычная формула Гаусса — за площадь проверенных контуров.
Аудит сохраняет исходную разметку. Подготовка растеризует валидированные цели и
применяет только явные коррекции с проверкой исходного хеша.

## Открытые научные вопросы

- Детекция, семантическая или экземплярная сегментация; единицы оценки результата.
- Один сосудистый класс или три подтипа; наличие экспертной разметки подтипов.
- Интерпретация unsure, гломерулов, сосудов на границе тайла и частично видимых объектов.
- Протокол экспертной проверки и допустимая полнота разметки для обучения/оценки.
- Разбиение по пациентам и WSI, предотвращение утечки перекрывающихся тайлов.
- Происхождение масштаба и корректность преобразования координат тайл ↔ WSI.

Реальный аудит и проверка прототипа описаны в [техническом отчёте](practice-audit.md).
После экспертной проверки и согласования постановки можно добавить явные
преобразования разметки и зафиксировать разбиение по происхождению данных.
