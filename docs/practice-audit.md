# Реальный аудит HuBMAP и проекта летней практики

Аудит выполнен 9 ноября 2026 года на исходных файлах `D:\БН\practica_work`.
Ревизия исходного кода практики `57de480`. Проверены `data/train`, `polygons.jsonl`,
`tile_meta.csv`, `wsi_meta.csv`, кэш масок, история обучения, код и три checkpoint.
Модельные эксперименты ограничены инференсом. SHA-256 всех 7 036 входных файлов
совпали в исходном и повторном прогонах аудита.

## Данные и качество аннотаций

Все 7 033 TIFF декодировались как одностраничные RGB-тайлы 512 × 512. Каждому
файлу соответствует уникальный `id` из `tile_meta.csv` и исходный `source_wsi`.
Всего 13 WSI. Таблица `wsi_meta.csv` содержит 4 строки для WSI 1–4. В ней
отсутствуют явные идентификаторы пациентов и подтверждённый физический масштаб.
В каталоге `test` есть один конкурсный пример с записью в `sample_submission.csv`.
В аудит `train` и прежнюю валидацию этот файл не входит.

В 1 633 непустых JSONL-записях 17 518 объектов. Дубликатов ключей, неизвестных
меток, аннотаций без тайла и выходов за границы изображения не обнаружено.
Каждый объект содержит один контур. 814 объектов (4,65 %) на 605 тайлах имеют
самопересечения по проверке Shapely. Из них 665 отмечены как `Ring Self-intersection`,
149 как `Self-intersection`. Для 16 704 геометрически корректных объектов выявлены
повторяющиеся вершины. Повторы сохранены в исходных записях. Полный перечень проблем
находится в `issues.csv` и `issues.json`.

Площадь вычислена для валидного полигона в координатах тайла. Число пикселей
в растровой маске зависит от растеризации. `geometry_statistics.csv` и JSON
дополнительно содержат распределения размеров и площади ограничивающего прямоугольника.
Для WSI 1 медиана площади `blood_vessel` составила 2 359 px² в Dataset 1 и 246 px²
в Dataset 2. В WSI 4 медиана составила 390 px². Такие различия требуют учитывать
происхождение и способ разметки при сравнении наборов.

Первый прогон ошибочно отметил 2 485 строк `tile_meta.csv` с ведущими нулями
в `i` или `j`. Аудитор теперь принимает такие десятичные записи и сохраняет
строковые значения. После исправления диагностированы те же 814 геометрических
ошибок и ни одного `invalid_tile_offset`. `--strict` завершился с кодом 1 после
сохранения всех отчётов. В 12 PNG наложены валидные контуры. Просмотрены примеры
`example_002.png` из Dataset 1 и `example_003.png` из Dataset 2.

Dataset 1 имеет статус экспертной проверки, полнота остаётся неизвестной.
Dataset 2 размечен разреженно, Dataset 3 не размечен. `unsure` остаётся исходной
категорией неопределённости. Аудит оценивает геометрию и связность записей.
Полноту и анатомическую точность разметки должен проверить эксперт.

## Разбиение и маски практики

`scripts/train.py` выбирает ID из JSONL, затем делит их по `source_wsi`.
Основной checkpoint подтверждает настройки `[1, 2, 3]` для train и `[4]`
для validation. Порядок ID восстановлен по исходному `tile_meta.csv`.

| Выборка | WSI | Dataset 1 | Dataset 2 | Всего |
|---|---|---:|---:|---:|
| Train | 1 (507), 2 (445), 3 (410) | 422 | 940 | 1 362 |
| Validation | 4 (271) | 0 | 271 | 271 |

Пересечение между выборками по WSI и ID пустое. Среди выбранных тайлов найдено
0 пар с идентичными байтами TIFF и 0 пар с идентичными декодированными RGB.
Проверка пациентов невозможна без явных связей WSI с пациентами. Проверка точных
дублей не охватывает приблизительные совпадения. Внутри train обнаружена 21 пара
пересекающихся прямоугольников на том же WSI, 20 из них между Dataset 1 и 2.
Расчёт предполагает, что `i/j` и сторона квадратного тайла выражены в одинаковых
пикселях. Для квадрата результат не зависит от порядка осей. Случайное разбиение
по тайлам или по номерам Dataset способно разнести эти области между выборками.

Все 1 633 PNG в `mask_cache` совпали пиксель в пиксель с повторной растеризацией
в памяти по алгоритму практики. Он заполняет `blood_vessel`, включая контуры с
топологическими ошибками, а остальные пиксели оставляет нулевыми. У 11 обучающих
масок нет положительных пикселей, у валидационных таких масок нет. Это свойство
старой целевой маски. Отсутствие пикселей класса не подтверждает отсутствие сосуда.
Кэш привязан к имени тайла. В старом коде нет проверки версии разметки, размера
тайла и параметров растеризации перед повторным использованием PNG.

## Checkpoint и повторный инференс

Три файла прошли проверку ZIP с ограничениями размера, числа записей и
метаданных. Десериализация выполнена на CPU с `weights_only=True` после
статической проверки globals, без дополнительных разрешений. Полученные
плотные конечные тензоры строго совпали с ключами и формами воссозданных
архитектур. Инициализация энкодеров выполнялась без скачивания весов.
Эта процедура применяется к трём известным локальным файлам. Ограничения
`weights_only` описаны в [документации PyTorch](https://docs.pytorch.org/docs/2.12/notes/serialization.html#weights-only-security).

| Checkpoint | Архитектура | Параметры | Метаданные внутри файла | Повтор на WSI 4 |
|---|---|---:|---|---|
| `best_model.pth` | U-Net, MiT-B2, SCSE | 27 602 264 | Эпоха 46, Dice 0,530069, порог 0,525 | Macro Dice 0,530061 без TTA при сохранённом пороге |
| `best_model_effb2_unetplusplus_0.5308.pth` | U-Net++, EfficientNet-B2, SCSE | 10 478 611 | Эпоха 29, Dice 0,508515, порог 0,50 | Macro Dice 0,508309 без TTA. Micro Dice с TTA 0,530774 при 0,50 |
| `best_model_resnet34_0.5566.pth` | U-Net, ResNet34 | 24 436 369 | Только `state_dict` | Micro Dice 0,557556 без TTA при пороге 0,50 по умолчанию |

Для EfficientNet-B2 число в имени соответствует округлению повторного **micro Dice
с TTA**, а записанное поле `val_dice` согласуется с **macro Dice без TTA**.
У ResNet34 имя файла и история Git указывают 0,5566. Исторический скрипт усреднял
Dice батчей размера 8 с весом по числу изображений. Измеренный micro Dice относится
ко всем пикселям WSI 4 и имеет другую агрегацию.

Проверка выполнена на RTX 5060 Laptop GPU с PyTorch 2.12.0+cu130,
torchvision 0.27.0+cu130, SMP 0.5.0, timm 1.0.27 и Pillow 12.2.0 из окружения
практики на Python 3.14.3. Проект аудита и его тесты работают на Python 3.12.
Для инференса использованы RGB / 255, маска `>127`, `eval()` и float32. TTA
усредняет четыре вероятностные карты после обратных отражений. Отчёты фиксируют
SHA-256 checkpoint, метаданных, TIFF и масок, а также порядок ID валидации.

| MiT-B2 на 271 тайле | Порог | Macro Dice, % | Micro Dice, % | IoU, % | Precision, % | Recall, % |
|---|---:|---:|---:|---:|---:|---:|
| Без TTA, сохранённый порог | 0,525 | 53,006 | 50,431 | 33,717 | 42,121 | 62,824 |
| TTA, тот же порог | 0,525 | 53,755 | 56,071 | 38,958 | 50,710 | 62,701 |
| TTA, максимум macro Dice на сетке практики | 0,55 | 53,615 | 56,490 | 39,363 | 52,991 | 60,483 |

Macro Dice усредняется по тайлам. Micro Dice и остальные показатели в таблице
вычисляются из суммарных пиксельных TP, FP и FN. Архивный результат 56,49 % с TTA
воспроизведён. Сохранённый Dice 53,01 % без TTA соответствует macro Dice.
Вычитание этих двух чисел смешивает агрегации. Для сравнения при пороге 0,525
прирост составляет 0,749 п. п. по macro Dice и 5,641 п. п. по micro Dice.
Порог 0,55 оптимален только на исторической сетке TTA с шагом 0,05, которая
не содержит 0,525. Отношение числа связных компонент предсказания к числу
компонент маски в `scripts/evaluate.py` не учитывает сопоставление объектов.
Его нельзя интерпретировать как полноту детекции.

## Что можно подтвердить о процессе обучения

- Конфигурация MiT-B2 задаёт до 70 эпох, батч 4, накопление 4 шагов, AdamW и
  смесь Focal/Dice/Lovász с весами 0,4/0,3/0,3. Сохранены эпоха, веса, порог
  и конфигурация. Состояния оптимизатора, AMP, генераторов случайных чисел и
  исходные списки ID не сохранены. `resume=True` восстанавливает веса и номер
  эпохи, при этом AdamW и AMP создаются заново.
- `training_history.csv` содержит 40 строк и максимум 0,5244 на эпохе 31.
  `scripts/create_history.py` строит CSV из массива чисел. Этот журнал не
  покрывает эпоху 46 основного checkpoint. Пиковый LR в журнале 0,0002, в
  конфигурации checkpoint LR декодера 0,0003. Однозначно связать журнал с
  полным запуском, давшим checkpoint, по имеющимся данным нельзя.
- `val_epoch` переключает модель в `eval()`, а `CombinedLoss` сохраняет
  режим обучения. Условие `self.training` поэтому оставляет label smoothing
  включённым при вычислении validation loss. Dice вычисляется отдельно по
  исходным бинарным маскам. В старой функции train Dice сигмоида зависит от
  знака минимального логита, что делает обработку логитов непоследовательной.
- WSI 4 использовался для выбора эпохи и порога, затем для подбора порога TTA
  и итогового отчёта. Это внутренняя валидация на одном WSI с разреженной
  разметкой. Неразмеченные сосуды могут учитываться как FP. Попиксельные метрики
  описывают согласие с имеющимися масками, а переносимость на другие WSI или
  пациентов требует отдельной проверки.

## Карта интеграции

| Компонент практики | Решение для нового проекта |
|---|---|
| `src/dataset.py`, чтение TIFF/JSONL | Использовать текущие адаптеры HuBMAP. Старое сопоставление ID и `source_wsi` подтверждено на реальных данных. |
| Растеризация и `mask_cache` | Сохранить алгоритм для сравнения с историческим baseline. Для нового представления явно задать целевые категории и правила `unsure`, пропусков и ошибок геометрии. Связать кэш с хешем источников и параметрами. |
| `scripts/train.py`, SMP и аугментации | Сохранить конфигурацию в качестве исторического эксперимента. После согласования постановки выделять только нужный адаптер обучения и тестировать согласованность преобразований изображений и разметки. |
| `scripts/evaluate.py`, Dice и TTA | Переиспользовать проверенные формулы с явным уровнем агрегации и фиксированным порогом на независимом наборе. Для оценки детекции понадобится сопоставление объектов. |
| `app.py`, `predict.py` | Переиспользовать идеи просмотра исходных контуров и результатов. `predict.py` использует ранний импорт `dataset` и корневой `best_model.pth`. Текущий `app.py` и resume в `train.py` явно вызывают `weights_only=False`, поэтому для проверки применён отдельный сценарий. |

Следующий шаг — экспертно проверить выборку контуров и договориться с руководителем
о детекции или сегментации, одном сосудистом классе или подтипах. Исходная метка
`blood_vessel` не различает капилляры, артериолы и венулы. До нового обучения
следует подтвердить происхождение пациентов, сохранить списки ID и хеши наборов,
выделить независимые WSI для итоговой проверки и зафиксировать правила работы
с разреженной разметкой. Результаты практики дают воспроизводимую точку сравнения
для бинарной сегментации, пока постановка дипломной задачи остаётся открытой.

## Воспроизведение

Полные артефакты находятся локально в `reports/hubmap-practica` и
`reports/practica-model/verified`. В Git хранится этот сводный отчёт и сценарии.
Используйте новые выходные пути для каждого запуска.

```powershell
$practice = 'D:\БН\practica_work'
uv sync --locked
uv run --locked kidney-vessels audit --input "$practice\data" --output reports/hubmap-repeat --examples 12 --strict
# Код 1 ожидаем при известных самопересечениях. Отчёт к этому моменту сохранён.
uv run --locked python scripts/audit_practice_data.py --input "$practice\data" --audit reports/hubmap-repeat --output reports/model-repeat/data-split.json --train-wsi 1 2 3 --val-wsi 4
```

Проверка checkpoint запускается в отдельном процессе с библиотеками практики.
Для структурной проверки достаточно вызова без `--evaluate`. Для повторного
инференса используйте следующие команды из корня основного проекта.

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:PYTHONPATH = "$PWD\src;$practice\.venv\Lib\site-packages"
$env:TORCH_HOME = "$PWD\.cache\practice-torch"
& 'C:\Python314\python.exe' scripts/audit_practice_checkpoint.py --practice $practice --device cuda --evaluate --output reports/model-repeat/mit-b2.json
```

Для двух других checkpoint передайте имя файла через `--checkpoint` и отдельный
`--output`. `--device cpu` позволяет выполнить инференс без GPU. В проверенном
прогоне SHA-256 каждого валидационного TIFF и входных метаданных сверены
с `manifest.json`, порядок ID сверён с отчётом разбиения.
